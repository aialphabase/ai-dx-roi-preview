# A/Bテスト実施案

## 目的

デザインの好みではなく、アンケート特典として「起動されるか」「最後まで使われるか」「次の行動につながるか」を比較します。

## 配信

- LINE配信対象をランダムに50:50でA/Bへ振り分ける
- 同一ユーザーは常に同じ案へ固定する
- 配信文、送信時刻、アンケート内容、相談導線は共通にする
- URLへ `variant`, `campaign_id`, `source` を付与する

例:

```text
https://example.com/pattern-a-dashboard.html?variant=A&campaign_id=bc-0730&source=line
https://example.com/pattern-b-roadmap.html?variant=B&campaign_id=bc-0730&source=line
```

## 主要KPI

| KPI | 定義 | 主目的 |
|---|---|---|
| 起動率 | 特典URLを開いた人数 / URL送信人数 | 特典としての魅力 |
| 入力開始率 | 1項目以上変更 / 起動人数 | 第一印象と入力意欲 |
| 結果到達率 | 結果を表示 / 起動人数 | 体験完了 |
| 相談希望率 | 相談希望ON / 結果到達人数 | 次の提案への接続 |
| 再訪率 | 7日以内に再度起動 / 結果到達人数 | カルテとしての継続価値 |

補助KPI:

- A案: シナリオ変更率、平均入力変更数
- B案: ステップ別離脱率、平均選択テーマ数
- 共通: LINE結果メッセージへの復帰率、予約ページ到達率

## イベント

実装済みのブラウザ内イベント:

- `karte_opened`
- `karte_input_started`
- `karte_scenario_changed`
- `karte_step_viewed`
- `karte_result_viewed`
- `karte_meeting_requested`

`window.dataLayer` が存在する場合は同名イベントを追加します。存在しない場合も `mirai:analytics` のカスタムイベントを発火するため、後から計測基盤へ接続できます。

## 判定ルール

- まず各案100完了を最低目安にする
- 結果到達率が5ポイント以上高い案を完了体験の優位候補とする
- 相談希望率は母数が小さくぶれやすいため、面談の質と合わせて評価する
- A案が起動率、B案が相談希望率で勝つ場合は、Aを入口、Bを会員向け本診断として併用する
- 期間中に質問・文言・配信条件を片方だけ変更しない

## 推奨する初回判断

A案とB案を完全な二者択一にせず、以下の組み合わせも有力です。

```text
LINEミニ診断
  -> A案で即時計算
  -> 結果画面からB案の詳細カルテ
  -> 高温度のみ個別相談
```

この構成ならA案の軽さとB案の情報量を両立できます。初回テストでは単独比較し、採用後に段階接続を検証します。
