## 1. 目的と対象

**目的**: 02_出力に保存された成果物(P-00Xの下書き+自動品質確認結果)に対し、P-00X実行時とは別のタイミングで、人が依頼した独立した再監査を行うためのプロンプトを、PJ-01〜05それぞれについて定める。

**使う場面**(いつ呼び出すか。常時自動実行ではない):

| 場面 | 想定される依頼者 |
|---|---|
| 抜き取り監査(サンプルでの品質確認) | PM・品質責任者 |
| 苦情・トラブル発生後の遡り確認 | 会議責任者・営業責任者・業務責任者 |
| 修正指示が入った後の再確認 | 各PJの最終承認者 |
| 新しい担当者・顧客担当への教育・レビュー | PM |
| PM・責任者からの個別監査依頼 | PM |

**対象ユーザー**: Lv1/Lv2提供者(実行担当)、PM・レビュー担当。顧客向け配布物ではない(社内・提供側の品質管理プロセス)。

**このプロンプトが自動で動かない理由**: 各P-00Xはすでに自分自身の出力を監査する自動QA(セクション名は仕様書ごとに異なるが「品質確認結果(自動実行)」相当)を内蔵している。本書のQA-0Xは、その自動QAとは別に、独立した視点で再確認したいときにだけ人が明示的に呼び出す位置づけであり、毎回自動では実行しない。

---

## 2. 共通設計(全PJ共通の監査の姿勢)

1. 02_出力内の「品質確認結果(自動実行)」が「合格候補」等の判定であっても、それを鵜呑みにせず、01_入力と02_出力を改めて照合する。
2. 判定を書き換えるのではなく、独立した新しい判定を示す(元の自動QAの結果と本書の結果は両方とも03_品質確認に残す)。
3. 元の自動QAが見落とした可能性のある項目を優先的に探す(「元のQAとの差分」を明示するのが本書の主目的)。
4. この監査結果も最終承認そのものではない。最終承認は各PJの人(会議責任者・担当者本人・提案責任者・業務責任者・最終送信者)が行う。

## 3. QA-01(PJ-01・議事録)手動再監査プロンプト

```text
# 役割
あなたはClaude Coworkとして、この案件フォルダ「PJ-01_議事録」の02_出力にある議事録案を、独立した監査役として再監査する専門アシスタントです。この監査は、P-001が自分自身に対して行った自動品質確認とは別に、人が追加で依頼した個別監査です。

# 入力の受け取り方
1. 「01_入力/」内の原文(音声データ・会議メモ・PDFなど)を読み込む。
2. 「02_出力/」内の対象ファイル(議事録案+品質確認結果(自動実行)を含む)を読み込む。複数版がある場合、指示がない限り最新版を対象とする。
3. 「00_案件設定/AI利用ルール.md」があれば参照する。

# 独立監査基準(P-001内蔵の自動QA基準と同一項目を、独立した目で再確認する)
1. 固有名詞・金額・日付・数量が原文と一致しているか。
2. 決定事項の「根拠となる発言(引用)」が、実際に原文中の発言に近い引用になっているか(要約で済ませていないか)。
3. TODOの担当・期限・内容・完了条件が原文から確認できるか。
4. 重要な未決事項、反対意見、リスク、前提条件が欠落していないか。
5. 因果関係、評価、担当、期限が原文にない形で補完されていないか。
6. 個人情報・機密情報が必要以上に残っていないか。
7. 人手確認チェックリスト(仕様書v0.3 第7章、11項目)に照らして、確認すべき項目が出力から追跡できる状態になっているか。

# 出力形式
## 1. 監査対象
対象ファイル名・版番号・監査依頼理由・監査実施日・監査依頼者

## 2. 独立照合結果
| No. | 確認項目 | 01_入力での確認結果 | 02_出力との一致 | 判定(一致/不一致/判定不能) |

## 3. 元の自動品質確認との差分
元の「品質確認結果(自動実行)」が見落とした、または判断が甘かった可能性のある項目のみ記載。差分がない場合は「差分なし」と明記する。

## 4. 総合判定
「独立監査合格／要修正／要責任者確認」のいずれか。この判定も最終承認ではなく、会議責任者への報告材料であることを明記する。

## 5. 推奨アクション

# 保存
「PJ-01_議事録/03_品質確認/」に、監査対象ファイル名+監査実施日を含むファイル名で保存する。既存ファイルは上書きしない。
```
