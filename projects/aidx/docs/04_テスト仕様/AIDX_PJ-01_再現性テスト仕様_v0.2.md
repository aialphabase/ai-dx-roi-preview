**成功指標**: 4系統すべてのゴールデンテストで、判断区分・必須見出し(10セクション)・要確認の扱い・発言引用の有無・禁止事項が一致すること(文章の一字一句一致は求めない)。合否ラインはv0.1から引き続き要確認(PM未確定)。

### 4.2 実行前必須入力チェック(停止条件)

Coworkフォルダ運用に合わせ、入力は「PJ-01_議事録/01_入力/」へのファイル配置で行う(コピペ貼付は前提としない)。

| チェック項目 | 必須/任意 | 不足時の挙動 |
|---|---|---|
| 01_入力/内の対象ファイル(音声・メモ・PDF等) | 必須 | ファイルが存在しない場合は実行不可として停止 |
| 会議名 | 必須(入力から読み取り) | 読み取れない場合「要確認」として出力(停止はしない、v0.3の設計通り) |
| 日時 | 必須(入力から読み取り) | 同上 |
| 目的 | 必須(入力から読み取り) | 同上 |
| 参加者 | 必須(入力から読み取り) | 同上 |
| 会議責任者 | 必須(入力から読み取り) | 同上 |
| 前回TODO | 任意 | 入力があれば「7. 前回TODOの確認」を出力、なければ当該セクション省略可 |
| 00_案件設定/AI利用ルール.md | 任意 | 存在しない場合は一般的な法人向け表現を使用(v0.3本文の記載通り) |

### 4.3 判定区分の固定ルールと根拠引用ルール

| 区分 | 定義 | 出力先セクション |
|---|---|---|
| 決定 | 会議責任者または明示された承認者による合意が原文で確認できる事項 | 4. 決定事項 |
| 未決・意見 | 検討中・提案・合意に至っていない事項 | 3. 主要論点・要点(意見/論点)、5. 未決事項・保留事項 |
| 要確認 | 担当・期限・決定者・数値・固有名詞などが原文から確定できない事項、または原文内で矛盾する事項 | 6. TODO内の該当欄、9. 矛盾・要確認一覧 |

**根拠引用ルール(v0.2で厳格化)**: 決定事項・TODOの「根拠となる発言(引用)・箇所」欄は、発言に近い短い引用(1文程度)を含めることを合格基準とする。v0.1では「発言者名+要旨」でも可としていたが、v0.3のP-001絶対ルール8・禁止事項(仕様書8章)により、要約のみの記載は不合格とする。引用箇所が特定できない場合は「根拠不明」と記載し、要確認一覧にも計上する。

### 4.4 出力仕様チェック項目(10セクション)

| No. | セクション | 必須表 | 上限・並び順 |
|---|---|---|---|
| 1 | 会議情報 | なし | 会議名/日時/目的/参加者/会議責任者の順、確認できない項目は「要確認」 |
| 2 | エグゼクティブサマリー | なし | 3〜5行 |
| 3 | 主要論点・要点 | なし | 最大5件、各項目に事実/意見/論点を明示 |
| 4 | 決定事項 | No./決定内容/決定者・承認者/適用日/根拠となる発言(引用)・箇所 | 決定なしの場合「明確な決定なし」と記載。根拠欄は引用必須(4.3参照) |
| 5 | 未決事項・保留事項 | No./論点/未決の理由/確認先/確認期限 | — |
| 6 | TODO | No./担当/期限/内容/完了条件/根拠となる発言(引用)・箇所 | 担当・期限不明は「要確認」、期限を推測しない。根拠欄は引用必須 |
| 7 | 前回TODOの確認 | TODO/状態/更新内容/次の対応 | 入力がある場合のみ出力 |
| 8 | 次回確認事項 | なし | 箇条書き |
| 9 | 矛盾・要確認一覧 | No./確認が必要な内容/理由/確認先候補 | — |
| 10 | 品質確認結果(自動実行) | 判定/指摘一覧(重要度・該当箇所・問題・原文根拠・修正案・人の確認要否)/未記載だが重要な事項/承認前チェック | v0.1には存在しなかった新規セクション。判定は「合格候補／要修正／保留」のいずれかで、人による最終承認前であることを明記 |

必須見出しの欠落は「0件」を合格ラインとする(v0.1から変更なし)。

### 4.8 入力形式に関する未検証事項(新設)

v0.3のP-001は「録音・文字起こしツールを使わず、生の音声データを直接Claude Coworkに渡す」ことを前提としている。しかし4.5のゴールデンテスト4件は、いずれも文字起こし済みのテキストを入力として設計されている(v0.1から流用したまま)。

### 4.9 人手確認チェックリストとの対応関係(新設)

PJ-01仕様書v0.3 第7章の人手確認チェックリスト(11項目)のうち、テスト出力から機械的に確認できる項目と、テスト実施者が別途確認すべき項目を整理する。

| チェックリスト項目(v0.3 7章) | 本書のテストで確認可能か |
|---|---|
| 1. 録音・音声データ提供の同意 | 対象外(テスト仕様の範囲外。運用側の確認事項) |
| 2. 承認されたClaude Cowork環境の使用 | 対象外(運用側の確認事項) |
| 3. 固有名詞・金額・日付・数量の原文照合 | T01〜T04で確認可能 |
| 4. 決定事項と意見・提案の混同なし | T01・T03で確認可能 |
| 5. 決定者・承認者の推測なし | T01・T02で確認可能 |
| 6. TODOの担当・期限・内容・完了条件の確認 | T01・T02で確認可能 |
| 7. 不明項目が「要確認」として残っている | T02・T03・T04で確認可能 |
| 8. 重要な反対意見・未決事項・リスクの欠落なし | T04で確認可能 |
| 9. 不要な個人情報・機密情報の削除 | T04で確認可能 |
| 10. 会議責任者の最終承認 | 対象外(テスト仕様の範囲外。運用側の確認事項) |
| 11. 承認版・版番号・保存先・更新責任者の記録 | 対象外(テスト仕様の範囲外。運用側の確認事項) |

11項目中4項目(1・2・10・11)はテストで確認できる性質のものではなく、運用ルール側の確認事項であることが分かった。この4項目をテスト仕様に含めるべきかどうかは対象外のまま置く。
