イベント管理ツール(Stripe連携) 開発可否 — 判断用

v0.1 / 2026-07-27 / 前提: 自社イベント専用・小規模(〜100名/回・月数回)・決済はStripe一本で確定 / 参考: イーベ！(event-form.jp)
開発 可能

要件5項目はすべて Stripe Checkout + 小さなWebアプリ で実現可能。技術的な未知要素なし。カード情報はStripe側に完全委譲(PCI DSS最軽量)。最大の作業は開発よりもStripe本番審査の準備物(特商法表記・返金ポリシー)。

要件 × 実現方式

要件実現方式難易度
イベントページ・申込フォーム管理画面でイベント登録 → 公開ページ自動生成低
申込時その場決済Stripe Checkout(ホスト型決済画面)。決済完了=申込確定。無料イベントはスキップ低〜中
支払済み/未払いの一覧WebhookでDB反映 → 参加者一覧(支払済/未払/キャンセル)+CSV低
申込上限数DBで定員管理(確定+決済中の仮押さえ)。Checkout失効(30分)で枠解放中
QR受付・出席管理参加者ごとに署名付きQRをメール送付。当日スタッフのスマホブラウザでスキャン→出席記録(専用アプリ不要)中

※ イーベ！の決済はfincode byGMO連携でStripe非対応 → 「Stripe一本」方針と既存サービス利用は両立しにくく、自社開発の判断と整合。

構成(最小)

参加者→ イベント公開ページ→ Stripe Checkout→ Webhook → アプリ本体+DB
Next.js / Supabase→ 確認メール+QRチケット→ 当日: スマホでQRスキャン→出席記録

開発と並行して必要な準備

  • Stripe本番アカウント申請(テスト環境は即日)
  • 特定商取引法表記・返金/キャンセルポリシーのページ(審査で実質必須)
  • プライバシーポリシー(参加者情報の取り扱い)
  • ドメイン+メール送信設定(SPF/DKIM — QR未達は受付破綻)
  • 当日運用の想定(受付スタッフ・紙のフォールバック)

主なリスク(いずれも運用系)

  • 返金時Stripe手数料3.6%は戻らない → ポリシーに反映
  • 満席間際の同時申込 → DBトランザクション+仮押さえ失効で制御
  • Webhook取りこぼし → 冪等処理+日次照合
  • 保守は自社持ち → 担当の明確化(西村さん想定)
